# Media security and resource policy

Only PNG/JPEG/WEBP are accepted: declared MIME, container structure and Pillow-decoded format must agree. Limit: 5 MiB, 2–4096 pixels per edge, 8 million pixels, one frame. PNG CRC/chunk/IEND, JPEG length-delimited marker/first real EOI, and WebP RIFF/chunk allowlist checks reject malformed/trailing polyglots. Animated input, GIF, SVG, PDF and executable formats are rejected. Unknown WebP chunks fail closed. This is not a proof against every possible embedded polyglot interpretation; originals are never served or executed.

Disposable image workers: 15-second wall time, ten-second CPU limit, 1 GiB memory, one native OpenCV thread, 256 KiB maximum JSON output. Windows job objects bound total memory/CPU, at most three processes, and kill descendants on close. Linux uses RLIMIT_CPU/RLIMIT_AS; Linux child-tree isolation still needs container/process-group verification. The linked scanner uses a separate 25-second killable worker with the same caps. Total work is sequential and bounded by both worker deadlines plus small startup/cleanup overhead. There are no retries. Worker input is stdin, output bounded JSON, never untrusted pickle. Fixed interpreter/module arguments are allowlisted; no shell or upload filename enters a command.

Tesseract temporary files use its library-managed cleanup. Upload originals are not persisted. C2PA cannot follow remote manifests/OCSP. No embedded markup, macros, scripts or XML external entities are executed. This process isolation is not a complete OS sandbox: workers retain the application's OS user privileges. Image workers receive a minimal environment without application secrets; linked scanner workers retain required application configuration. Container least privilege, network/filesystem policy and native-decoder vulnerability monitoring remain production requirements. Linux workers use a separate process group killed on cleanup; Linux aggregate memory/CPU accounting still requires container limits and platform verification.

Only the media multipart endpoint gets the 6 MiB request allowance; other JSON APIs keep 8 KiB. Existing same-origin, quota, concurrency, safe logging and response headers apply. Duplicate multipart fields/files and language-option injection are rejected. Sensitive media/OCR data is not logged.
