# Media intelligence — 10.0.0

`POST /api/v1/media/analyze` accepts multipart `file`, optional `language` (eng, hin, eng+hin, ara, chi_sim, fra, deu, spa), bounded JSON `email_context` using the existing Phase 9 schema, and optional `source_url` for an uploaded website attachment. Source claims are unverified; this endpoint does not download images or run email authentication.

Intake → disposable image worker → metadata, quality, measured forensics, OCR, QR, C2PA → one normalized extracted destination → disposable full Phase 2–9 scanner → Phase 6 media assessment → Phase 7 registered explanations and evidence graph. Source URL is analyzed only if the extracted-destination budget permits it. All URLs use existing DNS/IP-pinned retrieval; no second website scanner was written.

The response includes `artifact`, `metadata`, `quality`, `forensics`, `synthetic_media`, `ocr`, `qr`, `brand_analysis`, `provenance`, `investigation`, `linked_analysis`, `correlations`, `evidence`, `graph`, `assessment`, `explanation`, `errors`, and `analysis_status`. `investigation.checks` separates C2PA, metadata, AI-origin, measured manipulation clues, watermark, visual search and content-safety states; `coverage` records requested, completed, partial, failed, inconclusive, unavailable and not-checked work. C2PA manifest actions are allowlisted and returned without signer identifiers; verified signature and signer trust remain separate. Current successful intake returns PARTIAL because evaluated AI-image, watermark, public visual-search and content-safety providers are unavailable. Reverse search opt-in does not transmit until an approved provider is configured. Invalid media returns FAILED and UNKNOWN, with null risk. Synchronous bounded processing is used; there is no job persistence or async queue.

`POST /api/v1/media/investigate` accepts the same bounded image data in multipart field `image`, an optional comma-separated `checks` list, and explicit boolean `reverse_search` and `content_safety` requests. It returns the same response shape with a per-request unpredictable `investigation.scan_id`. These request flags do not bypass provider availability or produce simulated results.

Install `requirements-media.txt` and trusted Tesseract/language packs. Configure `TESSERACT_CMD` only through trusted server environment. Docker provisioning includes English and Hindi; other language packs must be separately provisioned. Original upload bytes are discarded after the request and never written to the repository.
