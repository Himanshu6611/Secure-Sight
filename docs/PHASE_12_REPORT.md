Status: **PARTIAL — working private dashboard and analyst workflow; full definition of done/public production readiness is not established.** The dashboard is a presentation layer. Existing Phase 6 verdict/risk/severity/confidence and Phase 7 explanations remain authoritative. No detection model was retrained and no second frontend scoring engine was introduced.

Implemented: unified security overview; tenant-scoped encrypted investigation history; normalized exact entity search; server-side date/verdict/severity/confidence/entity/domain/brand/source/evidence-type/status filtering; paginated investigation/evidence/timeline/graph APIs; separate assessment metrics; evidence IDs/provenance/types and reason references; modular domain/website/redirect/brand/history/email/authentication/attachment/media/OCR/QR/C2PA panels; accessible SVG graph inspection; chronological source timelines; investigation comparison; cases/verified evidence links/notes/review statuses; unvalidated feedback; authorized JSON/HTML exports; backend role/tenant enforcement; cookie CSRF; API-client bearer credentials; login/query limits; content-free HMAC audit chain; operator provisioning/revocation/purge commands; bounded tenant-scoped aggregate caching and descriptive analytics.

Authorized detector/API submissions are captured once. Async email jobs retain the authorized submitter and record successful or failed analyses privately. Anonymous scans are not stored. The adapter does not rescan, score, infer missing history or rewrite previous technical results. Reused website snapshots and copied linked assessments are deduplicated in presentation; unified backend graphs are preserved without adding redundant nested graph copies. Source/type search indexes can be backfilled from existing encrypted evidence without changing historical assessments.

A Phase 11 issue discovered during UI verification was corrected inside Phase 6: email-floor severity now uses its existing severity configuration. A score of 60 is HIGH under the current configured bands. This change does not create dashboard threshold logic or alter the verdict floor. Existing stored snapshots retain their original backend values; new assessments use the corrected policy.

## Privacy, operation and remaining limits

Private subjects, evidence projections, entity values, telemetry, cases and notes are encrypted in SQLite/WAL. Metadata indexes contain tenant IDs and bounded assessment fields; search terms use keyed hashes. No raw email body, original HTML or attachment bytes are stored in investigations. OCR text and returned investigation details are still private data. Local instance files are ignored by Git and have owner-only Windows ACLs. Local analyst credentials are in instance/dashboard-login.txt, not in this report or logs. Accounts are provisioned explicitly by an operator; tenant membership authorizes sharing within that tenant, not across tenants.

Production dashboard remains disabled unless an explicit durable DASHBOARD_DB_PATH and a dedicated DASHBOARD_ENCRYPTION_KEY of at least 32 characters are configured. Deployments must preserve and protect that key, private filesystem permissions and encrypted backups. SQLite is a single-host topology. Cookie sessions expire after one hour; CLI account deactivation revokes them on the next request. API_CLIENT tokens are distinct from email-job bearer tokens. HMAC audit chaining detects edits but cannot detect complete tail truncation without external anchoring; it is not WORM storage. A raw database/key compromise is outside this local audit guarantee.

Remaining Phase 12 work: full WCAG/screen-reader audit; realistic production/multi-worker load and deployment verification; distributed active-job analytics/durable export queue; broader comparison tooling and investigation lifecycle administration; sophisticated campaign/validated feedback/calibration/drift telemetry when trustworthy upstream data exists; sanitized full-email body/HTML previews if an appropriate explicit retention policy is added. Exports are bounded and synchronous; graph pages omit and count off-page edges. At most 2000 investigations and 500 cases per tenant, 512 graph nodes, 1024 graph edges/evidence rows, 1 MiB stored projections and 2 MiB exports bound work. Aggregate caches last five seconds and are keyed by tenant/validated filters.

Prior Phase 8 dynamic-browser, Phase 9 external-history, Phase 10 evaluated media-model and Phase 11 trusted-SMTP/SPF/email-model limits remain visible. Detection accuracy, the earlier PayPal false positive, calibrated public-web performance, Linux/container sandbox verification and public deployment readiness are not solved by a dashboard. No accuracy guarantee or public deployment is claimed.
