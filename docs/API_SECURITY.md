# API security

Public detector, feature/domain/web/ML and health routes retain existing anonymous access. Private dashboard/history/evidence/cases/export routes require the existing identity and tenant authorization. Every new protected route must use `require()` and store tenant predicates; frontend role display never authorizes a request.

Typed request/error contracts live in `app/security/json_policy.py`; runtime route validators enforce allowed/required fields and types, existing feature schemas and bounded context. No verdict/risk/tenant/role input is accepted into authoritative scan output. Unknown fields and duplicate JSON keys are rejected; non-finite numbers (including overflowed exponents), nesting beyond 16, collections beyond 1024 and more than 16384 JSON nodes fail before detector execution. Raw API JSON remains capped at 8192 bytes. Media multipart bypasses this JSON budget but stays within the global 6 MiB request cap. Email multipart is bounded further by its parser. Media context uses the same strict JSON parser. These contracts are manually validated, not a generated OpenAPI/Pydantic stack.

Origin checks cover POST/PUT/PATCH/DELETE. CORS is absent unless an explicit configured origin matches; only GET/POST/OPTIONS and Content-Type are permitted, with no credential flag or wildcard. Private cookie flows remain same-origin with CSRF. Authorization headers are not enabled for cross-origin clients by default.

The existing application POST IP quota defaults to 20/minute, additional authenticated account/token quota is 10/minute per detector endpoint (`ACTOR_SCAN_RATE_LIMIT`). Private reads are 120/minute per IP, login 10/minute. Production uses checked shared Redis; development memory limits are process-local. Identity/CSRF hooks precede actual scan-slot reservation. Case/feedback writes do not occupy detector slots. Rate failures carry 429 and Retry-After; busy capacity uses 503 and Retry-After, without a safe verdict.

Central HTTP errors use INVALID_INPUT, UNAUTHORIZED, FORBIDDEN, RESOURCE_LIMIT, RATE_LIMITED, PROVIDER_UNAVAILABLE and INTERNAL_ERROR. Existing detailed domain/media/email/model error codes are preserved for compatibility; INVALID_URL remains distinct. Error JSON includes a server-generated request ID; successful responses carry X-Request-ID. Exceptions expose no messages/stack traces. Security headers include CSP, nosniff, DENY framing, same-origin referrer, disabled camera/mic/geolocation and production HSTS. HTML export uses sandbox/default-src none. Legacy main-page CSP still permits its existing CDN assets/styles.

Phase 6 safety policy 6.2.1 blocks LEGITIMATE if any applicable intelligence stage is partial/unavailable/failed. Low observed risk then remains UNKNOWN, without changing numeric risk or promoting missing information to safety. Existing versioned historical snapshots are not rescored. Email and media already withhold safety labels. Supported complete observations may still produce a low-risk candidate; no verdict guarantees safety or model accuracy.
